# Action Bar

The action row at the foot of a form or dialog. It places each action by what it does, so every form in a product ends the same way and no one hand-aligns buttons.

## Three kinds of action

- **primary**: the one action that commits, such as Save, Create, or Send. It ends the row, at the
  inline-end edge. Give it `variant="solid"`; it should be the only solid button in the bar.
- **secondary** (the default slot, too): another way forward that changes nothing it cannot undo,
  such as Save as draft or Preview. It sits just before the primary action. Leave it the default
  `variant="outline"`.
- **tertiary**: a way back or out, such as Back, Cancel, or a safe Discard. It waits at the
  inline-start edge, away from the primary action. Give it `variant="ghost"` or `variant="link"`,
  with `tone="neutral"`, or `tone="danger"` for a destructive one.

The bar only arranges its actions; each button keeps the variant and tone you give it. The edges
are logical, so in a right-to-left page the primary action ends the row on the left. In a dialog,
put the bar in the `actions` slot and it fills the footer.

## Narrow containers

When the bar itself is narrower than 24rem (its own width, not the viewport's), it stacks its
actions full width: primary on top, then secondary, then tertiary. The width is fixed because
container queries cannot read custom properties. `--ui-action-bar-gap` sets the space between
actions, in a row and in a stack.

## Reading and focus order

Actions are in the source in the order a wide bar shows them: tertiary, secondary, primary. Reading
order and Tab order follow the row from its start edge to the primary action, so what a keyboard or
screen reader user meets matches what they see (WCAG 1.3.2 Meaningful Sequence, 2.4.3 Focus Order),
and the primary action is the last stop before leaving the form.

The narrow stack reverses the row visually so the primary action is on top, but the source and Tab
order do not change: they stay tertiary, secondary, primary at every width. Reordering the source
by width would make the sequence change as a user zooms in (which is when the stack appears), and
moving focusable elements would drop focus. The actions in a bar are independent of one another, so
their visual order in a stack carries no meaning that the reversed sequence loses.
