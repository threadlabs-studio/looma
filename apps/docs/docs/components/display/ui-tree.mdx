# Tree

An accessible hierarchy with disclosure, bounded logical indentation, and
truthful drag-and-drop previews. `ui-tree` coordinates the interaction while
`ui-tree-item` supplies rows and nested groups.


## Rows and their controls

A row is a grid of disclosure, leading content, label, and the `actions` slot. The actions overlay
the end of the row rather than taking a column, so **whatever you put in `actions` never changes
how wide a label is**: a long title runs the full width of the row and fades where the controls
begin, whether they are showing or not.

That means row controls need no width management of their own. Hide them with `opacity` or
`visibility` if they should appear on hover; there is nothing to collapse, and collapsing them
changes nothing about the label.

## Icons and links in a row

Put an item's icon in the `leading` slot and its name in the `label` slot. The label is what moves
when a long name scrolls (`marquee`) and what fades under the controls, so an icon inside the label
would move and fade with the name.

With `marquee`, a name too long for its row scrolls while a pointer hovers the row or keyboard
focus is on it. It fades out before the leading icon as it slides, rests at the end, then scrolls
again from the start until the pointer or focus leaves. A touch never starts it, so a swipe through
a long list stays still. Reduced motion keeps the fade and skips the scroll.

When a leaf row's label is a link, the whole row is that link: a click on its icon or padding
follows the link, with the same modifier keys, so a modified click still opens a new tab. Clicks on
controls (the move handle, anything in `actions`, including an item of a menu the row holds) keep
their own behaviour. With the default `selection="none"`, a branch row's click elsewhere expands
and collapses it.

## Selection

Set `selection="single"` to let a row click or Space request one selected item. Set
`selection="multiple"` to show checkboxes; choosing a branch requests it and its descendants
together. A partly selected branch shows a mixed checkbox. In either mode, the disclosure button
still expands the branch, and links and other controls keep their own action. The default `none`
keeps existing navigation trees from changing state on row clicks.

Tree selection is controlled: each Tree Item's `selected` prop draws the current state. A `select`
event reports `{ ids, trigger }` with the requested IDs in tree order; update those props from the
event. The tree sets `aria-multiselectable` in multiple mode. This keeps application data as the
source of truth when a list is loaded or reordered.

Tree rows share `--ui-selection-surface`, `--ui-selection-text`, and `--ui-selection-radius`
with navigation and other selected rows. Their faint accent surface and readable accent text derive
from the theme. The text token also reaches an automatic leading icon; an icon with an explicitly
supplied color keeps it. Selection does not change the label weight.

## Moving items

A `sortable` item shows a grip while its row is hovered. It sits beside what it drags: a leaf row has
no disclosure, so the grip takes that empty column right before the icon; a branch keeps its
disclosure there, so its grip sits just outside the row. The grip has no surface until it is pointed
at, then takes the hover tint. Dragging still works. A second path uses separate clicks or taps:
activate the grip, then click the destination row near its top, middle (to nest inside a branch),
or bottom. The destination marker shows the pending position. On touch, the grip stays visible and
has a 44px target.

With the grip focused, press Enter or Space to start a move. Up and Down choose a position before
or after a target; Right nests inside a branch, and Left returns to a sibling position. Enter places
the item and Escape cancels. The tree announces each choice. Both paths emit `reorder` and leave
the actual data update to your application. This pointer path satisfies the separate
[WCAG 2.2 dragging alternative](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements).

Typing the beginning of a visible item's name moves focus to it. A `lazy` Tree Item is expandable
before its children exist: opening it emits `expand` so the application can load children, and it
stays `aria-busy` until child Tree Items appear. Clear `lazy` if loading finishes empty.
