# List

A list of items: pages, people, sites, results. `ui-list` renders a native `<ul>` by default and
accepts direct `<li>` children. Set `as="ol"` for an ordered list and `markers="disc"` when bullet
markers help readers scan it. Use `ui-list-item` when an entry needs a consistent leading icon,
description, trailing action, or linked card layout.

## Structured entries

`ui-list-item` has four optional parts:

- **leading**: something to recognise it by, usually an icon or an avatar.
- **title** (the default slot): its name, on one line, ending in an ellipsis when it is too long.
- **description**: one line about it, such as where it lives and when it changed ("Planning · Edited
  2h ago"), muted and smaller.
- **trailing**: what it offers or says at a glance, such as a Restore button or a "Current" badge.

For ordinary prose lists, use native `<li>` children and let the content determine their shape.

## Rows and cards

`layout="rows"` (the default) stacks flat rows. `layout="grid"` sets items in as many columns as
fit. Add `class="card"` to a native `<li>`, or `variant="card"` to a structured `ui-list-item`, for
a bordered surface. Use cards for a handful of featured or pinned entries.

## Links

In a structured item, put a link in the title and the whole item follows it: the icon and padding
are part of the link's hit area, and the item takes the link's hover surface and focus ring. It
stays a real link, so a router link, a modified click, and "open in new tab" all work. A control in
`trailing` keeps its own clicks. An item with no link has no hover surface, so it does not look
pressable. Native `<li>` children retain normal link behavior.
