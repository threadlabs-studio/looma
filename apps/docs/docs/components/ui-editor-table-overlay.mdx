# Editor Table Overlay

Boundary-aligned controls for inserting rows and columns around the active table.

## Component Reference

<ComponentExamplesApiTabs component="ui-editor-table-overlay" />

## Runtime Contract

`LoomaEditor` sets `open`, `rows`, and `cols` from the active table and maps
boundary intent to Tiptap commands. Advanced consumers using the primitive
directly receive `looma-editor-table-overlay-action` with
`{ action, boundaryIndex }`.

Pointer hover and keyboard focus reveal the affected boundary. Focus must remain reachable without hover, and touch integrations need a visible table-toolbar path because hover does not exist. The overlay is client-generated enhancement UI and has no no-JS fallback. The editor table content remains independent of it.

Row and column insertion remains available from the visible table toolbar on
touch devices. Pointer users also get boundary controls; native Tiptap column
resize handles keep drag resizing available between columns.

On narrow screens, tables retain minimum-width cells inside a horizontal scroll
wrapper. The hover overlay stays off because touch has no hover state; equivalent
row and column actions remain available from the single mobile table dock.
