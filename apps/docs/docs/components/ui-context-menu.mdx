# Context Menu

Action menu with a visible keyboard/touch trigger plus supplemental pointer-context support.

## Component Reference

<ComponentExamplesApiTabs component="ui-context-menu" />

## Semantics And SSR Markup

Put a native button in the `trigger` slot. The optional `for` attribute adds `contextmenu` handling to a larger region without replacing that visible action path.

```html
<div class="document-row" id="document-row">
  <ui-context-menu for="document-row">
    <button slot="trigger" type="button">Document actions</button>
    <ui-menu-item value="rename">Rename</ui-menu-item>
    <ui-menu-item value="delete">Delete</ui-menu-item>
  </ui-context-menu>
</div>
```

## Interaction Contract

- The visible trigger opens by click/touch activation, `Enter`, `Space`, or `ArrowDown` and focuses the first enabled item.
- Pointer context-menu on the optional `for` target opens at the pointer coordinates.
- `Enter` or `Space` activates the focused enabled item; `Escape` dismisses.
- Selection, cancellation, and outside press return focus to the visible trigger.
- `open`, `close`, and `select` events use the same trigger/reason vocabulary as Looma menus.
- Disabled items do not emit selection.
- Touch uses the visible native trigger; browser-dependent long-press behavior is supplemental only.
- Before upgrade, the author-provided item text remains in light DOM, but positioning, dismissal, and selection behavior do not. Do not rely on this element as the only no-JS action path.

## Vue

```vue
<script setup lang="ts">
import { ContextMenu, MenuItem } from "@threadlabs/looma/vue";
</script>

<template>
  <div class="document-row">
    <ContextMenu @select="({ value }) => runAction(value)">
      <button slot="trigger" type="button">Document actions</button>
      <MenuItem value="rename">Rename</MenuItem>
      <MenuItem value="delete">Delete</MenuItem>
    </ContextMenu>
  </div>
</template>
```
