# Input

A native input with Looma’s shared control theme. Optional segments support block selection, character filtering, automatic or typed separator advancement, and continuous authentication-code entry.

## Sizes

Every form control takes the same `size` as [Button](/components/ui-button), so one size across a row
lines up: see the Compact row example. `md` is the default. An [Input Group](/components/ui-input-group)
takes its input's size, so a small input makes a small group.

| Control | `sm` | `lg` |
| --- | --- | --- |
| Input, Select, Combobox | Shrinks to the small control height (2rem), with tighter padding and smaller text; Select's chevron shrinks too | Grows to 3rem, with roomier padding |
| Textarea | Tighter padding and smaller text; `rows` sets the height | Roomier padding |
| Checkbox, Radio, Switch | Aligns rather than shrinks: the box or track keeps its size, the label takes the smaller text, and its first line centres in the small control height | Aligns the same way: the label keeps body text and its first line centres in the 3rem height |

On touchscreens, editable fields use body-size text. Their visible size ladder remains shared with
buttons; hit areas are a separate, context-dependent concern.
`size` is Looma's option, not the native attribute: an Input fills its container's width (give it
a character width through its hook, such as `--ui-input-inline-size: 12ch`), and a Select is always a single-choice dropdown
(use a `multiple` Combobox for a list that shows several choices at once). A numeric `size` fails the
option's type. To change the size after a field renders, set the option: the Vue `size` prop, or a DOM
factory's props. The rendered element's own `size` property is the native input's or select's, and
its `data-size` attribute only records the option.

## Numbers

A `type="number"` or `type="range"` field's value is a number. In Vue, bind `v-model` to a number
or `null` for no value. A number field reports a number as the user types and `null` while it
holds no number yet, such as when it is empty or reads `1e`. The same value types apply to
`value` and `update:modelValue`.

```vue
<script setup lang="ts">
const quantity = ref<number | null>(1);
</script>

<template>
  <Input v-model="quantity" type="number" min="0" step="0.5" />
</template>
```

Bound to a number, the field never writes over what the user is typing while it means the same
number: `12.` on the way to `12.5`, `1.0`, `1e3`, and an empty field all keep the text, the caret,
and any trailing zero. Bound to text instead, each keystroke's number differs from the bound text,
so the field is rewritten on every update: typing `12.5`, Backspace, then `8` loses the point.

## Styling hooks

An input follows the global control tokens (`--ui-control-border`, `--ui-control-surface`, and so on).
For a form-wide change, set the inherited `--ui-field-radius` or `--ui-field-danger` on the form:
Input, Input Group, Select, Textarea, Combobox and Form Field pick up the relevant value together.
See the [three theming levels](/tokens). To restyle one input, set its own hooks on that input through
a class of your own. Set the same hooks on `:root` or an ancestor to style a group of inputs:

| Hook | Sets |
| --- | --- |
| `--ui-input-border`, `--ui-input-border-hover`, `--ui-input-focus-border` | the border at rest, under the pointer, and when focused |
| `--ui-input-border-width` | the border's width (`1px`) |
| `--ui-input-inline-size` | the width (`100%`, the container's), such as `12ch` for a short field |
| `--ui-input-min-block-size` | the minimum height (the control size) |
| `--ui-input-surface` | the fill |
| `--ui-input-radius` | the corner radius |
| `--ui-input-shadow`, `--ui-input-focus-shadow` | the inset shadow at rest and the focus ring |
| `--ui-input-invalid-border`, `--ui-input-invalid-focus-shadow` | the border and focus ring of an invalid input |
| `--ui-input-focus-outline` | the focus ring under forced colors, which drop box shadows (`2px solid Highlight`) |

[Input Group](/components/ui-input-group) sets the input's defaults below those hooks to draw one field around an input and its
affixes: fixed text before or after the value, such as `https://` or `.example.com`. The input keeps
its behaviour there, and the group's page lists what it guarantees: one tab stop, a lone Input's
focus ring, affixes that focus the input when pressed, and affixes read as the input's description.


## Edit blocks progressively

Set `segments` to a list of editable blocks and fixed separators. An editable block
has a `placeholder` and a `pattern` matching one allowed Unicode character. Its
placeholder length determines how many characters fit. Hint text uses the native
placeholder attribute and never becomes the input value. Partial entry contains
entered characters and separators. A separator has `literal`
instead. For example, hours and minutes use:

```html
<ui-input value="09:30" segments='[{ placeholder: "hh", pattern: "[0-9]" }, { literal: ":" }, { placeholder: "mm", pattern: "[0-9]" }]'></ui-input>
```

Focus selects the first block. Type a complete block or its separator to advance.
Arrow keys move between blocks; Backspace clears or moves back. Adjacent one-digit
blocks support authentication codes with `autocomplete="one-time-code"`. The
control remains one native input for selection, clipboard, autofill and submission.
Use native `pattern` and `required` attributes to validate a completed code.
Date Field and Time Field configure localized date and time blocks automatically.
