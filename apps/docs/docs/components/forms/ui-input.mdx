# Input

Text input that lowers directly to a native `<input>` while applying Looma's shared control theme.

## Sizes

Every form control takes the same `size` as [Button](/components/ui-button), so one size across a row
lines up: see the Compact row example. `md` is the default.

| Control | `sm` | `lg` |
| --- | --- | --- |
| Input, Select, Combobox | Shrinks to the small control height (2rem), with tighter padding and smaller text; Select's chevron shrinks too | Grows to 3rem, with roomier padding |
| Textarea | Tighter padding and smaller text; `rows` sets the height | Roomier padding |
| Checkbox, Radio, Switch | Aligns rather than shrinks: the box or track keeps its size, the label takes the smaller text, and its first line centres in the small control height | No `lg` |

Under a coarse pointer, `sm` grows to the 44px touch minimum, as a small Button does, and the text
fields keep body-size text, because iOS zooms the page into a focused field whose text is under 16px.
`size` is Looma's option, not the native attribute: an Input fills its container's width, and a Select
is always a single-choice dropdown.

## Styling hooks

An input follows the shared control tokens (`--ui-control-border`, `--ui-control-surface`, and so on).
To restyle inputs alone, or one input from a parent, set its own hooks, which fall back to those:

| Hook | Sets |
| --- | --- |
| `--ui-input-border`, `--ui-input-border-hover`, `--ui-input-focus-border` | the border at rest, under the pointer, and when focused |
| `--ui-input-surface` | the fill |
| `--ui-input-radius` | the corner radius |
| `--ui-input-shadow`, `--ui-input-focus-shadow` | the inset shadow at rest and the focus ring |
| `--ui-input-invalid-border`, `--ui-input-invalid-focus-shadow` | the border and focus ring of an invalid input |

[Input Group](/components/ui-input-group) uses them to draw one field around an input and its affixes.
